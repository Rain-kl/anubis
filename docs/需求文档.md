
Anubis WAF 二次开发需求文档

一、项目背景

当前系统已有基础访问控制机制：
	•	认证方式：PoW（Proof of Work）验证
	•	校验方式：通过认证后签发 JWT
	•	访问控制逻辑：持有有效 JWT 的用户可访问系统资源

现需扩展系统能力：
	1.	增加新的「校验模式」
	2.	增加新的「认证模式」
	3.	支持认证方式与校验方式解耦组合

⸻

二、需求一：新增校验模式（Validation Mode）

2.1 现有逻辑
	•	用户通过 PoW 验证
	•	服务端签发 JWT
	•	后续请求通过验证 JWT 访问系统

当前仅支持：

校验模式：jwt


⸻

2.2 新增校验模式：IP 白名单机制（whitelist）

目标

新增一种访问控制模式：
	•	用户通过认证后
	•	不再签发 JWT
	•	将用户 IP 加入白名单
	•	白名单有效期默认 1 小时
	•	每次请求自动刷新过期时间（滑动过期）

⸻

2.3 校验模式设计

系统新增配置项：

valid_mode:
    - jwt        （原 JWT 模式）
    - whitelist  （IP 白名单模式）


⸻

2.4 whitelist 模式行为逻辑

认证成功后：
	•	获取用户真实 IP
	•	将 IP 加入白名单
	•	设置 TTL = 1 小时
	•	存储：内存缓存

⸻

访问请求校验逻辑：
	1.	读取请求 IP
	2.	查询是否存在于白名单
	3.	若存在：
	•	允许访问
	•	刷新 TTL（重置为 1 小时）
	4.	若不存在：
	•	拒绝访问
	•	返回认证入口

⸻

2.5 滑动过期机制

行为说明：
	•	每次有效请求
	•	自动延长有效期
	•	类似 Session Sliding Expiration

示例：

时间	行为
10:00	认证成功，过期时间 = 11:00
10:30	访问成功，过期时间刷新为 11:30
11:20	访问成功，过期时间刷新为 12:20


⸻

2.6 默认参数

参数	默认值
白名单有效期	1 小时
是否滑动刷新	是
存储后端	Redis（建议）


⸻

三、需求二：新增认证模式（Authentication Mode）

3.1 现有认证模式

当前仅支持：

auth_mode:
    - pow

认证成功后，进入校验流程。

⸻

3.2 新增认证模式：密码认证（password）

目标

新增一种简单的密码认证机制：
	•	用户输入密码
	•	服务端验证密码正确性
	•	验证通过后颁发进入许可

⸻

3.3 新增认证模式配置

auth_mode:
    - pow
    - password


⸻

3.4 password 模式行为逻辑

流程：
	1.	用户访问系统
	2.	进入密码认证页面
	3.	用户输入密码
	4.	服务端验证：
	5.	验证成功后：
	•	进入校验流程（见 validation_mode）

⸻

四、认证模式 + 校验模式组合逻辑

认证与校验解耦，形成可组合结构：

auth_mode	valid_mode	行为
pow	jtw	原有逻辑：签发 JWT
pow	whitelist	IP 加入白名单
password	jwt	签发 JWT
password	jwt	IP 加入白名单


⸻

统一流程模型

用户访问
   ↓
认证流程（pow 或 password）
   ↓
认证成功
   ↓
校验模式处理
   ↓
jwt → 签发 JWT
whitelist → IP 加入白名单
   ↓
允许访问


六、安全性考虑

6.1 密码模式安全建议
	•	限制错误尝试次数
	•	增加延迟防止暴力破解
	•	建议支持 fail2ban

总可配置参数新增:

1. auth_mode
2. valid_mode
3. password
4. whitelist_timeout (秒)
